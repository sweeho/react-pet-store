## Legacy Implementation Architecture

### Credit Card Entity Model

**CreditCardEJB** (`components/creditcard/ejb/CreditCardEJB.java`)

- Container-managed persistence (CMP) entity bean
- Primary key: Implicit (auto-generated by container)
- CMP fields: cardNumber, cardType, expiryDate (all String)
- Implements CreditCardLocal interface
- Transaction attribute: Required for all methods
- Access control: Unchecked (no authorization)

### Credit Card Fields

- **cardNumber** (String): Payment card number
- **cardType** (String): Card type identifier (VISA, MASTERCARD, AMEX, etc.)
- **expiryDate** (String): Card expiration date stored as "MM/YYYY" format

### Database Persistence

**CreditCardEJBTable** DDL (from sun-j2ee-ri.xml):

```sql
CREATE TABLE "CreditCardEJBTable" (
  "__PMPrimaryKey" LONGINT,
  "__reverse_creditCard___PMPrimaryKey" LONGINT,
  "cardNumber" VARCHAR(255),
  "cardType" VARCHAR(255),
  "expiryDate" VARCHAR(255),
  CONSTRAINT "pk_CreditCardEJBTabl" PRIMARY KEY ("__PMPrimaryKey")
)
```

All credit card fields stored as VARCHAR(255).

### Credit Card Creation

**Three creation paths:**

1. **No-argument create()** - Creates empty CreditCard entity
2. **Three-parameter create(cardNumber, cardType, expiryDate)** - Creates with values
3. **DTO create(CreditCard)** - Creates from CreditCard transfer object

All paths delegate to ejbCreate() which calls individual setters.

### Expiry Date Parsing

**getExpiryMonth():**

- Parses expiryDate string for "/" delimiter
- Returns substring before "/" (month portion)
- Default: "01" if string is null or "/" not found

**getExpiryYear():**

- Parses expiryDate string for "/" delimiter
- Returns substring after "/" (year portion)
- Default: "2010" if string is null or "/" not found

### Data Transfer Object Pattern

**CreditCard.java** (POJO):

```java
public class CreditCard {
  private String cardNumber;
  private String cardType;
  private String expiryDate;
  // getters and setters
}
```

Used for copying data between EJB entity and other components.

**CreditCardEJB.getData():**

- Instantiates new CreditCard POJO
- Copies entity fields (cardNumber, cardType, expiryDate) to POJO
- Returns populated POJO for transmission to other components

### Transaction Management

All CreditCardEJB methods have trans-attribute="Required" in ejb-jar.xml:

- create() overloads
- findByPrimaryKey()
- remove()
- All getters (getCardNumber, getCardType, getExpiryDate, getExpiryMonth, getExpiryYear, getData)
- All setters (setCardNumber, setCardType, setExpiryDate)

Container ensures atomic execution and rollback on error.

### Authorization

```xml

    <ejb-name>CreditCardEJB</ejb-name>
```

All methods accessible without role-based restrictions.

### JNDI Integration

**Registration** (sun-j2ee-ri.xml):

```xml
<ejb-name>CreditCardEJB</ejb-name>
<jndi-name>ejb/petstore/customer/CreditCard</jndi-name>
```

**Usage in other components** (AccountEJB):

```xml

<jndi-name>ejb/petstore/customer/CreditCard</jndi-name>
```

Components access CreditCard EJB via JNDI lookup: `InitialContext.lookup("java:comp/env/ejb/CreditCard")`

## Known Limitations

1. Hardcoded default expiry values ("01" and "2010") - unclear if intentional
2. Expiry date stored as String requiring parsing - no date type validation
3. Card number stored in VARCHAR(255) - no field length constraints visible
4. No visible validation of card type values
5. No visible credit card number encryption or masking
6. No audit trail for credit card operations
7. String parsing for date extraction is error-prone
8. No configuration for default expiry values
9. DTO pattern requires manual copying - no automatic mapping
10. All credit card methods unchecked - financial operations have no access control
